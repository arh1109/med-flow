MedFlow pytest bootstrap
========================

1. Add development/test dependencies:

    uv add --dev pytest pytest-asyncio httpx

If aiosqlite is not needed because these tests use PostgreSQL directly.

2. Create a separate PostgreSQL database ONE TIME:

    psql -U postgres

Then in psql:

    CREATE DATABASE medflow_test;
    \q

If your normal database is named medflow_dev_2478, conftest.py will derive
medflow_dev_2478_test instead. Create that database name rather than
medflow_test.

You can see your active database name from DATABASE_URL in .env.

3. Put the files at:

    backend/
    ├── app/
    ├── tests/
    │   ├── conftest.py
    │   └── test_database.py
    └── pytest.ini

4. Run from backend/:

    python -m pytest -v

Expected initial result:

    test_database_connection PASSED
    test_database_can_persist_model PASSED
    test_database_is_clean_between_tests PASSED
    test_health_route_uses_test_client PASSED


IMPORTANT
---------

conftest.py derives the test DB from settings.database_url:

    medflow -> medflow_test

and refuses to run unless the resolved database name ends with "_test".

That guard is intentional. pytest should never create/drop tables in the normal
MedFlow development database.


OPTIONAL TEST_DATABASE_URL SETTING
----------------------------------

If you want a completely explicit test URL, add this to Settings:

    test_database_url: str | None = None

and to .env:

    TEST_DATABASE_URL=postgresql+asyncpg://postgres:YOUR_PASSWORD@127.0.0.1:5432/medflow_test

If you do not add this setting, conftest.py simply derives the test URL from
settings.database_url.


WHY POSTGRESQL INSTEAD OF SQLITE?
---------------------------------

MedFlow uses PostgreSQL/asyncpg behavior including enums, UUID refresh-token
chains, constraints, foreign keys, and transactions. Using PostgreSQL for route
and integration tests keeps the test environment much closer to the actual
application.
